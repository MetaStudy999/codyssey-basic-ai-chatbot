## 1. 팀 프로젝트의 고정 목표
팀원은 Discord에서 토론하고 실제 역할별 과제를 수행한다. AI Assist는 명시적으로 허용된 채널의 메시지/슬래시 명령을 근거로 요구사항·결정·할 일을 수렴하고, ChatGPT 주도의 Agent Codyssey MCP → WSL2 Codex 개발·시험·증빙에 연결한다. GitHub에 작업 이력을 남기고 AWS 개인 계정에 *승인 후* 서비스를 배포한다. 팀원 최종 승인과 실제 기여는 AI로 대체하거나 허위 작성하지 않는다.

## 4. Discord AI Assist — 선택 협업 확장
**최소 기능:** 동의한 채널에서 슬래시 명령 `/assist`, `/review`, `/status`, `/decision`을 접수하고 작업 ID·요청자·채널·승인 상태를 기록하여 진행 현황을 반환. 일반 채널 전체 대화 자동 수집이나 DM 읽기는 초기 범위 제외. 팀원 동의·Discord 권한·필요한 인텐트 확인 후 범위 확장 가능.

**주요 계약:**
- `/assist task <요구>` → 태스크 초안·담당자 추천 → 팀 책임자 승인 → GitHub Issue/허용된 Codex 개발 작업
- `/review <PR>` → 승인된 저장소의 PR 상태·검증 결과 요약 (병합 자동 금지)
- `/status <작업ID>` → 해당 작업의 검증된 상태·최근 결과 요약
- `/decision <안건>` → 의견/대안/결정 책임자 기록, 합의 미확정은 PENDING
- 계정/채널/역할 권한과 도구 실행 권한을 분리. **Discord 메시지를 곧바로 운영 셸 명령으로 실행하지 않음**.

## 5. 간소화 아키텍처 (미배포 제안)
```text
팀원 Discord 지정 채널
  → Discord Application/Bot (서명 검증된 Interactions 또는 허용된 이벤트)
  → 개인 AWS의 HTTPS API 경계 (서버 인증·요청 검증·중복 차단)
  → 업무 큐/승인 정책 → AI Assist 요약·계획
  → Agent Codyssey MCP → 기존 WSL2 Codex 개발/시험
  → 기존 GitHub 미션 저장소 (이슈·브랜치·PR·증빙)
  → AWS에 배포한 B7-1 FastAPI 웹 서비스 + DB
  → Discord 작업 상태/결과 공유
```
최소 경로에서는 기존 FastAPI HTTPS 서버에 Discord 명령 엔드포인트를 합치는 방안부터 평가한다. 자동 큐·전용 인프라는 실제 병목이 있을 때만 추가한다. Discord 앱 인증과 ChatGPT 연결은 별개이며, ChatGPT가 Discord에 상주하거나 채널을 자동 감시하는 기능은 **현재 연결되지 않음**.

## 6. 개인 계정 및 안전 권한
- **Discord 개인 계정:** Owner가 앱 생성·봇 초대/승인, 서버·채널 권한과 팀원 공지/동의를 직접 설정해야 한다. 봇 토큰은 절대 채팅·GitHub에 게시 금지.
- **AWS 개인 계정:** Owner 명의로 비용·IAM 권한 관리. AWS Budgets 알림/금액 한도, 최소 IAM 권한, 지역·서비스 제한을 먼저 검토. 실제 배포·유료 리소스 생성·권한 변경·삭제는 별도 명시 승인 전 미실행. 예산 알림만으로 비용 발생이 강제 중지되지는 않는다.
- **팀 데이터:** 지정 채널에서 동의한 메시지만 사용; 외부 AI API 전송 전 개인정보·비밀값 제거; 증빙은 원문 대화와 AI 생성 요약을 구분. 로그 접근권한·보존 기간·삭제 책임자를 팀과 결정.
- **운영 통제:** 팀이 승인한 작업만 Codex에 전달; 기존 Job ID 조회 후 신규 32자리 ID로 단회 실행. AI의 PR 병합/배포/삭제/권한확대 자동 결정 금지.
